| Source Domain | Original Action / Verb | Reason for Exclusion (which Criterion fails) | Conditional note (when to **keep**) |
|---|---|---|---|
| System / Network | `heartbeat` (connectivity heartbeat) | Fails **Policy Relevance** and **Social State Change** — purely infrastructural, no intent-boundary or change to commitment state. | Include only if heartbeat carries an explicit negotiation payload or requests a policy decision. |
| System / Network | `trust_ping` / `ping` (connectivity probe) | Fails **Social State Change** — mechanical probe verifying connectivity; no independent counterparty decision. | Include if repurposed as an application-level solicitation requiring a response/consent. |
| Local OS / Filesystem | `filesystem_read` / `read-local` | Fails **Counterparty Existence** — unilateral local read against passive resource, no second agent with independent agency. | Include remote document access *requests* (e.g., “request access to /shared/doc”) that involve another actor. |
| Background Service | `keepalive` / `TCP keepalive` | Fails **Policy Relevance** — maintenance of channel health only, not an intent/decision point. | Include if the keepalive triggers policy decisions (e.g., “keepalive indicates policy breach — do you revoke?”). |
| Telemetry / Monitoring | `telemetry_export` / `metrics push` | Fails **Social State Change** — reporting/monitoring without intent to alter commitments between agents. | Include the *incident report* or enforcement action that consumes telemetry. |
| Logging subsystem | `log_write` / `audit-log entry` (automatic) | Fails **Policy Relevance** and often **Counterparty Existence** — local recording is not an agentic negotiation. | Include if the log write *automatically* creates a regulatory filing or notifies another agent who must decide. |
| Mobile App / Browser | `background_sync` (automatic sync) | Fails **Policy Relevance** when automatic — preserves channel state rather than proposing a cross-agent commitment. | Include if sync requires consent from, or changes relationship with, another actor (e.g., share contacts with third party). |
| Mobile OS / Presence API | `presence_broadcast` ("user is online" passive) | Often fails **Policy Relevance** / **Social State Change** — passive presence maintenance does not itself change social commitment. | Include if presence announcement explicitly invites/initiates a negotiated interaction (e.g., “I’m online — start paid session?”). |
| IoT / Local Device | `config_local` (volume/brightness adjust) | Fails **Counterparty Existence** — a unilateral local device setting that does not involve another independent actor. | Include remote control requests that require owner consent (then map as /govern/permit or /operate/actuate). |
| Webhook / Integration | `status_webhook` / health-status webhook (one-way) | Fails **Policy Relevance** — one-way status notification without an intent boundary or decision request. | Include webhooks that explicitly solicit action/consent (e.g., "Confirm refund?"). |
| Software Update Service | `auto_update_push` (forced update) | Fails **Policy Relevance** if fully automatic — infrastructure/maintenance operation without negotiation. | Include update flows that require user permission/consent to change policy or data sharing. |
| Market Data Provider | `price_ticker` / market-feed broadcast | Fails **Policy Relevance** when purely informational — a broadcast that does not itself instantiate a commitment or require accept/decline. | Include price *quotes* that are firm offers (“take this quote to execute trade”), which are agentic. |
| Identity / PKI Service | `identity_heartbeat` / cert-validity probe | Fails **Policy Relevance** if purely mechanical — binary connectivity/validity check without negotiation. | Include credential presentations or verification requests that affect access/consent. |
| OS / App Permission Model | Permission *labels* (e.g., `READ_CONTACTS`, `ACCESS_FINE_LOCATION`) | Fail **Counterparty Existence** and **Policy Relevance** as *row items* — these are parameter tokens, not agentic interactions by themselves. | Include **permission requests** (app asks user to grant `READ_CONTACTS`) which are in-scope agentic interactions. |
| Local Backup System | `scheduled_backup` (local-only backup) | Fails **Counterparty Existence** and **Social State Change** — private maintenance task that does not alter inter-agent commitments. | Include backups that transfer data to third parties (cloud backups requiring consent) — then they are in-scope. |
